# Hijack 菜单 + 设置窗口 HCI 评审(第二轮,2026-10-01)

**结论:** 窗口已经承担了"设置"的角色,菜单却还保留上一轮"没有窗口时"的全量设计,两处各有一套叫法。下一步是**给菜单减重**(只留状态 + 两个高频切换),把**词表统一到一份**。另有一个数据丢失问题要先修:配置文件解析失败时,菜单不显示任何错误,用户再点任一设置就会把他手写到一半的文件整份覆盖掉。

## 1. 问题清单

| # | 级别 | 问题 | 启发式 | 修法 |
|---|---|---|---|---|
| 1 | **Blocker** | `config.json` 解析失败时,`lastError` 只在窗口顶部显示红色横幅,菜单里没有任何提示。之后菜单或窗口里的任一次修改都会调用 `save()`,用内存中的旧值整份重写文件,用户手写的那份(包括未识别的键)直接丢失 | Nielsen #1 系统状态可见、#5 防错、#3 用户控制 | 有 `lastError` 时:菜单状态区加一行 `⚠︎ 配置文件有错误,改动暂停 — 打开查看… / Config file has an error — Open…`;所有写操作禁用(菜单项置灰,窗口控件 `.disabled`),直到文件能解析为止。另外把横幅改成 HIG 的黄色警示样式,不用红底白字 |
| 2 | **Major** | 首次运行:只弹出系统权限框,不打开窗口。辅助功能权限放在第 3 个标签页"通用",而第 1 页"试一下"在没有权限时按了也没反应,不说明原因 | Nielsen #9、#10;HIG onboarding | 首次启动(或没有权限时)打开设置窗口到"听写"页;"试一下"上方显示 `需要辅助功能权限 [去允许…]`;拿到权限后自动消失并启用"试一下"。"通用"页的权限行保留 |

## 2. 推荐结构

**统一词表:** 快捷键 Shortcut · 按住说话 Hold to Talk · 点按开始,再点停止 Tap to Start, Tap to Stop(两处都去掉"免按")· 语音来源 Dictation Source(标签页也用 **Source / 语音来源**)· `X 里的语音键` / `X's Voice Key`(窗口里来源名已作为行标题,可以写成"语音键 / Voice Key",但不用"它的")· 启动方式 / Starts Listening On · 自动检测 Detected · 默认值,未验证 Default, Unverified · 恢复自动检测 Use Detected · 配置文件 Config File。

**菜单(中文 / English):**
```
按住右 Option 用微信输入法听写            Hold Right Option to dictate with 微信输入法   [灰]
⚠︎ 需要辅助功能权限 — 去允许…              ⚠︎ Needs Accessibility — Allow…              [仅异常,可点]
⚠︎ 配置文件有错误 — 打开…                  ⚠︎ Config file has an error — Open…           [仅异常,可点]
⚠︎ 微信输入法里的语音键未确认 — 设置…      ⚠︎ 微信输入法's voice key unverified — Settings… [仅异常,→ Source 页]
────
✓ 按住说话                                 ✓ Hold to Talk
  点按开始,再点停止                          Tap to Start, Tap to Stop
    再点一下,或按任意键停止 [灰小字]             Tap again or press any key to stop
  快捷键:右 Option ▸                        Shortcut: Right Option ▸
     同微信输入法里的语音键 (Fn) / ── / 右 Option / 左 Option / 右 Command / Fn / ── / 其他按键…(→ 设置窗口)
────
  语音来源:微信输入法 ▸                     Dictation Source: 微信输入法 ▸
     ✓ 微信输入法 / Handy / ── / 语音来源设置…(→ Source 页)
────
  设置…                       ⌘,           Settings…                    ⌘,
  退出 Hijack                 ⌘Q           Quit Hijack                  ⌘Q
```
- 语音键子组从菜单移到窗口。它是一次性配置项,而且已有自动检测;检测失败时状态区的 ⚠︎ 行会直接链到 Source 页。**这一条我不完全确定**:如果用户经常在 Handy 里改键,保留在菜单里也说得过去。
- "其他按键…"打开窗口里的录制器,不再打开 JSON。
- 菜单里去掉"听写方式"小标题:单选组上下都有分隔线,分组已经清楚。

**窗口:**
- **听写 / Dictation:** 方式(radio)→ 免按停止开关 → 快捷键弹出菜单 → 试一下(卡片内,紧接在快捷键下面,没有权限时在这里提示)。
- **语音来源 / Source:** 单选列表(包含配置文件中的未知来源)。每行:名称 + `语音键 Fn · 自动检测` 摘要 + `选项…` 展开(语音键录制、启动方式)。下方是空状态或页脚。
- **通用 / General:** 不变。"在菜单栏显示图标"和"在 Dock 显示图标"同时关闭时,加一行说明:`两者都关闭时,再次打开 Hijack 即可回到这里`。
- **高级 / Advanced:** 修对齐;建议把"配置文件"行从通用页移到这里(它属于高级用户入口)。**不确定**:放在通用页也符合不少 app 的做法。

## 3. 优先级前五

1. **解析错误时冻结写入,并在菜单状态区显示错误**(#1,防数据丢失)。
2. **首次运行打开窗口 + "试一下"处的权限提示**(#2)。
3. **统一词表,两处共用一张字符串表**,同时修中英混排(#3、#13)。
4. **菜单减重**:移除开机启动、菜单栏图标、语言、编辑配置文件和语音键子组;"其他…"改为跳到窗口(#4)。
5. **Sources 页渐进披露 + 显示未知来源 + 无障碍 radio**(#5、#7、#8);快捷键改成弹出菜单(#6)可以和这一项一起做。
