## Hijack 1.1.4

- **The menu tells you when the shortcut cannot work.** When macOS turns off the key listener, or Secure Input is on (a password field), the menu bar icon shows a slash and the first menu line names the cause and the step. `hijack status` and `hijack doctor` now report the same state. Before, they said "active" after the listener had died.
- **A stuck talk key gets released.** If Hijack quits while it holds the talk key, the next start releases it. If the system turns the key listener off during a hold, Hijack releases the key when the listener comes back, and after sleep or unlock. The menu shows "Hijack is still holding …" with a Release action while a session is stuck.
- **"Try it" stops saying things that are not true.** It no longer says "Listening…" when the voice tool's microphone stays off, and it no longer says "back to …" before the switch back is confirmed.
- **No talk key to the wrong input source.** When the switch to the voice input method does not land within one second, Hijack ends the dictation instead of sending the key to whatever is active. Before, Fn alone could open the macOS dictation panel.
- **Chained dictations switch back again.** Pressing the shortcut while the previous text is still arriving kept the voice input method active at the end. Fixed.
- **Settings apply when the file changes.** Hijack watches the config file and the voice tool's settings with FSEvents instead of a one-second poll. Idle CPU went from 130 ms to 10 ms per minute.
- **`hijack stats`.** Success rate, failure causes, p50/p95 latencies and incidents, from the one-line-per-dictation log.
- **Engine behind seams, fault-injection tests.** Key posting, input sources, the event tap, probes, the clock and the log sink are protocols with fake implementations. 83 tests (from 17): the failure modes in `docs/fmea.md` each have a test that reproduces them. Reviews in `docs/review-4/`, decisions in `docs/adr/`.
